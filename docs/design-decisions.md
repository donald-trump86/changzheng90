# 四渡赤水：实现中的设计取舍

本次实现遵循已批准的[设计说明](superpowers/specs/2026-10-22-chishui-design.md)、[文案定稿](copy-deck.md)与 [name-as-monument 方向](../.taste-skill/direction.json)，种子为 `1099683438`。没有重新抽取方向。

在本页，赤水河两岸的反复跨越成为阅读顺序与版面的组织方式。四个字占据近乎整行的宽度，宋体字形形成开场的主体；标题之后，地图与正文并列。手机上保留完整四字标题，把地图放在正文上方，按钮留在文流中。标题下另设“开始阅读”，窄屏读者不必先滚过地图才找到入口。

配色保留冷雾白、深松绿、岩石灰、灰青河水与暗红路线。标题与章节标题使用本地中文宋体栈，正文使用本地黑体栈。没有在线字体、图片、脚本或运行时依赖。系统字体在不同设备上的字面和字重会有差异，真实排版由控制器的专用浏览器 QA 核查。

## 原创地图

地图为代码绘制的原创 SVG：三层山形、山体折面、单条弯折河流与具名渡口组成同一幅山川图。山形承接两岸地貌的阅读感受，路线箭头表达跨河方向；不加入坐标网格、测绘刻度或卫星纹理。

图中用上北下南的概略排列呈现元厚、土城、太平渡、二郎滩、九溪口与茅台；扎西、川南及黔北作为方向性参照。渡口不按比例定位，路线不代表精确行军轨迹，山形不代表真实地形。图中同时显示“西／东”文字、箭头和章节名称；当前路线为暗红实线，先前各渡为低对比虚线。跳到任意一章时，先前章节仍以累计留痕呈现，本章路线需读者主动展开。封面和尾声显示全程概览。

主要图注放在 SVG 外，使用正文大小。图中地名在窄屏缩放后作为辅助标注；本章渡口、完整方向与局势、行动、结果均在外部文本和 SVG 无障碍说明中提供。控件不压在图上。

## 对方向表的必要适配

方向表的满屏摄影英雄、城市图片、人物肖像及商业介绍分区与本作的史实阅读用途不符，因此采用已批准设计中的原创河流图。没有下载或使用方向表中的照片，也没有将虚构照片表现为历史影像。保留巨大标题、紧凑外边距、平静正文与明确色面的构图关系。

四次渡河由可直接选择的章节按钮组织，不套用需要旋转窄条或固定高度的横向手风琴；手机保留可读正文。尾声以真实后续行动、明确标为作者解读的感想和两道理解题收束，没有添加营销分区。

动效只用于本章路线描绘、展开文字的短距离出现以及按钮反馈。`prefers-reduced-motion` 下立即呈现完整内容，不等待动画结束。未为技能中的照片数量或入场动效计数增加素材。

## 交互与输出

所有历史正文、题目、来源与纪念卡日期从[故事模块](../src/story.js)消费。HTML 的无脚本全文按同一文案静态保留，并在 Node 检查中逐字段对照。阅读进度不存储；刷新回到封面，未知 hash 回到封面。跳转、前后翻章均收起当前路线与说明。

来源使用原生 `dialog`，保留 Esc、关闭按钮、外部点击与焦点恢复。理解题使用原生单选按钮，可重选，不计分。纪念卡在本机 Canvas 生成，显示预览、下载链接和打开图片入口；替换图片时释放旧 Blob URL。导出失败显示重试与截图保存建议，阅读仍可继续。

纪念卡的路线是比主图更简化的原创四次跨河示意，日期与西／东方向仍由共享章节读取。卡片包含署名与预定域名，不代表访问凭证或机构认证。

## 验证边界

本实现任务按控制器要求没有启动任何浏览器、CDP、截图工具或 taste 独立检查器。已进行 Node 测试、模块语法检查、无脚本文本一致性断言、地图渲染状态契约检查、构建白名单及短时 HTTP 检查。320／390／768／1440px 的真实排版、键盘行为、减少动态效果及 PNG 解码由控制器在后续专用 Brave QA 中检查；此处不提供未经实测的视觉分数或截图结论。
