# 四渡赤水：当前实现的设计取舍

## 连续阅读与历史顺序

首页围绕“赤水河，为什么要渡四次？”组织内容，依次呈现开篇、长征背景、四次渡河、后续历程与影像档案。四章全文直接写在[首页](../index.html)，无脚本也能按链接定位阅读。[历史数据](../src/story.js)保存四章事实、来源、分期与时间线；修改时应核对 HTML 和地图数据，避免日期、渡口及方向漂移。

[滚动控制器](../src/history-scroll.js)以视口45%处的阅读线选择当前章节，按当前位置处理反向滚动与大幅跳转，不依次补播已跳过的章节。手动章节导航保留，原生滚动与键盘操作不被接管。当前渡次同时更新导航、日期、地图和已开启的配乐。

## 地图与屏幕空间

桌面地图随正文保持可见；窄屏将同一张地图移到当前章节之后，避免长期固定层遮挡阅读。区域总览帮助理解川黔滇边的机动关系，渡河细看只突出局部河段；全部路线用于比较四次转向，重播用于观察当前路线。

地图将十个现代地点参照、历史渡河概略区域和行军概括线分层。九溪口保留与太平渡的关系说明，不补造坐标；娄山关按上下文位置标为概略节点。底图来自90点现代高程粗采样，不表现为1935年地表复原。出处和派生许可见[素材清单](assets.md)。

## 纸墨、照片与动效

[图册样式](../src/print-atlas.css)采用纸色、深墨、灰蓝河道与克制的暗红强调，以朱雀仿宋显示子集和系统后备字体建立题字与正文层次。静态纸纹只用于页面材料，不改写历史照片的像素。

开篇河谷图明确标为生成艺术示意。两张历史照片保留原始字节、完整画面和比例，图注直接说明年代、出处和不能据此认定的事件。原图对话框提供放大、缩小与复原，关闭后恢复触发点焦点。

[编辑动效](../src/editorial-motion.js)承担分组入场、路线描绘、河面流线和阅读进度。自托管 Anime.js 是增强层，并保留内置 rAF 降级路径。暂停、系统减少动态和页面生命周期处理应让内容回到可读状态；实际效果以当前浏览器验收为准，不从代码参数推断视觉通过。

## 可选配乐

[音频控制器](../src/audio.js)独立于动画。页面默认关闭配乐，用户显式开启后才加载和播放；第1—2章使用 Scott Buckley《Undertow》，第3—4章使用《The Great Sea》，换曲以320ms交叉淡化衔接。音量可调，页面隐藏或离开时暂停，返回后需重新开启。过期播放承诺与渐变回调受代次状态约束，避免暂停后重新出声。

两首曲目按 CC BY 4.0 保留作者、作品页、许可及使用说明，见[音频版权页](../audio-credits.html)与[音频授权](audio-rights.md)。配乐是当代作品，不作为历史录音或史料。

## 维护边界

运行资源随站点同源托管，静态正文优先，浏览器增强逐层接入。地图、字体、观察器或音频不可用时的实际行为需要专项验证。当前验证与待办见[验证记录](verification.md)，发布方式见[部署说明](deployment.md)。
