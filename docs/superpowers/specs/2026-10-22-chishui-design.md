2026-10-22。用户选择方案 C 并明确要求开始，执行方式为子代理开发。以下实现细节由助手作出，可在本地预览后调整。

## 用途与核心问题

为“红色初心·长征礼赞”网络文化作品征集制作原创静态互动 H5，纪念红军长征胜利 90 周年。作品面向用手机、微信打开的学生及评审，回答：中央红军为什么在赤水河两岸反复机动？读者用约 3 分钟看清四次渡河各自的局势、行动和变化，理解实事求是、主动调整与坚定目标的关系。

作品标题为“四渡赤水”，副标题“为什么这样走”。界面直接说明“沿四次渡河，读懂中央红军如何从被动转向主动”。不把历史做成可改写结局的指挥游戏，不虚构对白、心理活动、精确兵力或路线轨迹。

## 内容与史料

主史料：https://www.news.cn/politics/2016-10/02/c_129309668.htm （新华网，2016-10-02，来源中央纪委监察部网站）。第二官方来源由内容任务实际读取后登记。

一渡以 1935 年 1 月 29 日拂晓作为开始，土城战斗未获预期战果后，从土城、元厚等渡口西渡，脱离堵追。二渡为 2 月 18—21 日，从太平渡、二郎滩等渡口东渡，利用敌军被吸引至川滇边境、黔北相对空虚的形势，随后取得遵义战役胜利。三渡为 3 月 16—17 日，在茅台一带西渡。四渡为 3 月 21—22 日，从太平渡、二郎滩等渡口东渡，随后南下。三渡、四渡的具体局势须以第二来源复核后填写。

四渡结束不等于长征结束，也不等于当日完全摆脱所有围堵。尾声明确后续南渡乌江、威逼贵阳、巧渡金沙江是之后的行动。战略目标和行动方案会调整，不把四次渡河写成事先排好的四步计划。

每章含 date、title、situation、action、result、insight、sourceIds 以及地图路线阶段。内容来自结构化数据，界面与分享卡日期不得各自硬编码。地图为原创概略路线示意，标注“路线为概略示意”，不画国界，不冒充精确战场复原。渡口与主要地名位置关系须合理，地图叙事中明确西渡/东渡，预览不得仅凭颜色区分当前章。

## 阅读流程与交互

1. 开场：可见标题、主题描述、原创山川路线图和“开始阅读”按钮。首次加载即可读，无强制加载动画。
2. 四次渡河：每章先读局势，再由“展开路线”显示本章路线与行动结果。随后“下一渡”推进，另有“上一渡”和四章直达按钮。当前章与累计路线切换同步。读者可以跳读、回看，不设倒计时。
3. 尾声：用真实后续行动收束，明确作品对当代学习与做事的启示是作者解读。提供“回看全程”“制作纪念卡”“史料来源”入口。
4. 两道轻量理解题：围绕“路线为何调整”“四渡之后发生什么”，回答后解释，不设排行榜或虚假分数。选择错误可重新选择。
5. 纪念卡：Canvas 在本机生成 PNG，含标题、四次渡河日期、原创路线图简化图形、作品作者戴诗旭、目标域名 changzheng90.luvch1nabest.me。不是参观证书，不预填读者身份，不上传用户数据。支持下载；无法下载的浏览器可打开本地生成图长按保存。
6. 史料来源：原生 dialog 或等价可访问对话框，含可点击来源、地图说明、原创设计与署名。支持 Esc、关闭按钮、点击外部关闭，打开后焦点位于对话框，关闭后回到触发按钮。

无 JavaScript 时提供四章全文与史料链接，内容不能永久隐藏。刷新默认回到开场；没有保存进度需求。未知 URL hash 安全回到开场。任何快速连点、任意章跳转、先回看再展开都不能残留其他章节内容。

## 视觉方案

使用 frontend-design 与 design-taste-frontend 的原则。主视觉来自赤水河弯折与四次跨越：在本页，“赤水河上的反复跨越”成为叙事与版面的组织方式。地图与路线是作品本身的图像，不套商业产品的卡片网格。

色彩采用冷雾白背景、深松绿文字、岩石灰山形与暗红行军路线；赤水河为灰青色。标题使用有中文表现力的宋体/衬线系统字体栈，正文使用中文黑体系统栈；不从 Google Fonts 或 CDN 加载字体。大字、地图与文本形成明确主次，正文至少 16px。桌面用地图与章节文本并列，手机用短地图画面在上、清楚的叙事在下，底部控制不遮挡正文。320px、390px、768px、1440px 均无横向溢出。

地图内小点、线、地名是信息图标记。选择态用字、形和色共同表达。按钮触控区至少 44px。动效用于当前路线描绘、章节切换和按钮反馈；支持 prefers-reduced-motion，减少动效时立即展示完整路线。没有自动音视频、WebGL、随机漂浮装饰或必须动画结束才能操作的阻塞。

设计技能随机方向须先抽取并记录，采用其中与主题相符的构图。交互地图作为 data-ui 区域；如网页检查器针对普通营销页的图片数量或八个入场动效要求与历史互动应用冲突，记录理由，优先采用用户明确指定 frontend-design 的“稀疏且有意义的动效”和本说明的原创地图，而不为达标加入无关照片或运动。

## 架构与技术

采用无运行时依赖的 HTML/CSS/ES modules，Node >=22 内建测试，开发服务器为 Node 标准库。本地静态文件一并托管，无 API、数据库、账号、统计、远程图片或外部脚本。package.json 用于 npm run dev、npm test、npm run build。构建输出 dist/，可直接部署到 GitHub Pages；页面路径均为相对路径，支持仓库子路径预览。

源文件分工：src/story.js 为史料与纯状态逻辑；src/map.js 为 SVG 地图与路线；src/main.js 为 DOM 与事件；src/share.js 为 Canvas 导出；src/styles.css 为全部样式；index.html 为语义骨架与无脚本全文。scripts/serve.mjs 和 scripts/build.mjs 为开发与构建；tests/story.test.js 验证状态切换与准确日期，tests/site.test.js 验证构建资源完整；浏览器行为检查脚本可置于 scripts/verify-browser.mjs，不进入部署输出。
