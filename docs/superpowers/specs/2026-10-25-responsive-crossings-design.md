# 四渡赤水滚动与移动端地图设计

状态：待用户审阅。本文的交互细节和技术选型是本轮建议，尚未改动产品代码。

## 目标与依据

让读者在手机上按历史顺序阅读四次渡河，地图始终属于它所说明的内容；桌面保留对照正文的交互地图。“把四渡放回长征”配四次渡河的完整概览，不能默认配第一渡，也不能随下面的章节变化。

用户指出手机屏幕尺寸影响四渡展示，以及长征背景段目前与第一渡地图并排的问题，提供 [Lenis](https://github.com/darkroomengineering/lenis) 和 [Three.js](https://github.com/mrdoob/three.js/) 作为参考，并调用 writing-plans、frontend-design、apple-design、design-taste-frontend。

保持现有木刻开篇、纸墨配色、历史正文、史料说明、党徽和配乐，只调整背景与四渡阅读区域及其共用滚动入口。历史数据以 [history-data.js](../../../src/history-data.js) 为准；地图继续使用 [historical-map-data.js](../../../src/historical-map-data.js) 的既有概化几何。

## 当前问题与实测

- [首页](../../../index.html#L269) 的 `grid-template-areas: "context map" "crossings map"` 让同一地图跨越背景和正文，初始方向、日期和路径都是第一渡。
- [首页](../../../index.html#L662) 的 `placeRouteSheet()` 在手机切章时将整张地图插入当前文章之后，再用 `window.scrollBy(0, delta)` 补偿位置，改变了控制器正在测量的章节几何。
- [响应式样式](../../../src/print-atlas.css#L1688) 缩为一列时没有清掉双列命名区域；CSS 的900px与JS的899px分界也不一致。
- [滚动控制器](../../../src/history-scroll.js#L117) 用视口高度的45%判断章节，页面又叠加根滚动留白与章节留白。短屏上的导航落点可能位于阅读线之后，保持700ms不能保证最终章节正确。
- [地图尺寸计算](../../../src/historical-map.js#L66) 只约束图面，没有一起计算标题、控件、长说明和版权文字的高度。

2026-10-25在本地 `http://127.0.0.1:4173/`、专用Brave中读取页面标题、尺寸并查看截图：

| 视口 | 观察 |
| --- | --- |
| 1440×900 | 背景时间线旁为“一渡·西渡”，全部路线关闭；sticky地图整块高约1215px。 |
| 390×844 | 第一渡后的地图整块高约1297px，实际图面约258×211px；说明比图面占用更多空间。 |
| 768×1024 | 地图被搬入正文；外层仍保留双列命名区域，实际列宽约686.5px与0px。 |
| 844×390 | 本次直接打开 `#crossing-two` 后活动章为二渡，但加载完成仍在页首，二渡标题在视口下方。 |

截图已查看，尺寸来自DOM测量；没有据此宣称真机Safari、微信内置浏览器或帧率通过。证据持久副本及测量记录位于 `artifacts/scroll-plan-before/`。

## 内容与视觉决定

本页独有的材料包括赤水河、1935年1—3月、土城与元厚、太平渡与二郎滩、茅台、扎西集中、川南机动、西—东—西—东的转向、1935年到达陕北与1936年会师的区别，以及已有木刻渡口图。这些材料决定布局，不另做一套首页视觉。

页面主线：先用长征时间线定位四渡，再用四条路线建立整体关系；四个章节分别说明情势、方向、行动与结果；随后保留南渡乌江、威逼贵阳、巧渡金沙江等后续历程。四次西东往返是总览与分章阅读之间的对应关系，读者可以点选章节，也可以直接读完四章。

沿用六个色彩角色：纸色 `#F0E8D8`、阅读面 `#F7F1E3`、墨色 `#211F1C`、路线红 `#9B302B`、河道灰蓝 `#6E8A93`、辅助灰 `#67635C`。标题沿用 `ChishuiAtlasDisplay`，正文用现有系统黑体；正文至少16px，操作目标至少44×44px，辅助色只用于图注。图文区不增加装饰框线、玻璃层、悬浮胶囊或卡片。

这是已有页面的局部结构调整，按design-taste-frontend的单区块规则匹配现有方向，不随机抽取新风格，也不新增素材或动效数量指标。

## 布局与响应式行为

桌面背景区（宽度至少901px）：

```text
┌───────────────────────┬───────────────────────┐
│ 把四渡放回长征        │ 四渡赤水总览          │
│ 1934—1936时间线       │ 四条路线同时呈现      │
│ 1935与1936节点区别    │ 西渡 东渡 西渡 东渡   │
└───────────────────────┴───────────────────────┘
```

总览属于背景区，不参与章节地图状态。标题为“四渡赤水总览”，描述覆盖四次方向，图例按一渡至四渡排列；四条线使用同一红色系，以不同虚线样式和文字图例区分，不能只靠颜色。由构建时SVG呈现，无脚本也有完整四条线，并注明为阶段概括线。

桌面四渡区：标题与章节导航在上，正文在左，单个交互地图在右，DOM位置固定。只有短标题、日期、控件、图面与简短图注进入固定单元；完整说明、图例解释、来源和版权位于四章之后的普通文档流。地图方法说明只保留一处完整版本，各图通过链接指向它。

手机与平板（宽度至900px）：

```text
把四渡放回长征
1934—1936时间线
四渡赤水总览（完整四条路线）

四次渡河，形势在变
一渡  二渡  三渡  四渡
[交互地图：比较路线、查看渡口] 可展开

一渡标题、日期、主题句
一渡渡河简图
当时情势 / 行动与结果

二渡标题、日期、主题句
二渡渡河简图
当时情势 / 行动与结果
……
地图依据与完整说明
```

各章简图使用该章 `geometry(number, 'detail')`，图注明确“渡河方向示意；不是本阶段全程”，只画相关河段、方向和已核的渡口区域。二渡、四渡的多个渡口不能画成依次到访的路径。简图放在主题句之后、情势正文之前；滚动回调不插入或移动节点。

完整交互地图只有一份，放在四渡区开头的原生 `details.map-explorer` 中。手机初始折叠，仍可展开区域总览、渡河细看、全部路线与重播；展开后普通滚动，不固定顶部、不限制页面滚动。桌面增强成功后展开并作为右侧地图。窄屏转桌面时展开，桌面转窄屏时保留已展开状态，不因旋转关闭正在使用的控件。桌面隐藏summary前必须先打开details；无脚本时summary始终可见可操作。

宽屏短视口（高度小于600px）也显示分章简图，取消sticky。固定模式必须同时满足宽度至少901px、高度至少600px，并且固定单元实测高度不超过可用视口；字体放大或控件换行超出预算时，也退回普通流。根据尺寸而非UA判断。CSS与JS统一以 `min-width: 901px` 为宽屏条件。

## 滚动与章节状态

保留 [createHistoryScroll](../../../src/history-scroll.js) 的阅读线、反向滚动和单帧合并，只观察 `article.chapter-panel[data-chapter]`，不将SVG上的同名属性误作章节。

移除 `placeRouteSheet()`、相应宽度监听和被动切章的滚动补偿。被动切章只更新导航、日期、地图和已开启配乐，不写URL、不移动焦点、不滚动文档。

所有显式导航共用落点：目标标题在顶部以下24px；极短视口将其限制在阅读线之前16px。清除旧的双重root padding和chapter margin，无脚本锚点保留24px章节留白。章节按钮、上一渡/下一渡、初始深链接和hash变化遵守同一规则。导航期间可暂时保持目标章，完成或被用户打断后立即恢复当前位置判断，不能只靠固定700ms。

保留真实hash、前进后退、链接修饰键与新标签页行为。字体加载后最多校正一次初始深链接；一旦用户滚动、触摸或按导航键，即停止自动校正。迟到的旧回调不能覆盖新选择。

Lenis仅在 `(hover: hover) and (pointer: fine)`、未要求减少动态且 `body[data-motion]` 不为 `off` 时实例化；`syncTouch: false`，手机原生触摸。建议 `autoRaf: true`、`smoothWheel: true`、`lerp: 0.12`、`anchors: false`、`respectReducedMotion: true`。锚点由页面统一处理，避免两路导航；取消全局CSS smooth，显式导航由统一入口选择原生平滑或立即跳转。

Lenis导入失败继续原生，不锁输入、不用 `lock: true`。滚动中的滚轮、触摸与导航键能取消旧目标。图片对话框滚动区标记 `data-lenis-prevent`，不截获其内部滚动。页面隐藏或pagehide时销毁实例并取消待完成导航；pageshow或重新可见时按当前媒体条件重建，保留位置。控制器已经销毁时，迟到的导入结果不得创建实例。

## 地图与动效边界

背景总览和四张章节简图都是构建时静态SVG，使用独立title、desc和marker ID，不复制 `#route-map`、`#current-route` 或live地图data属性。保留现有单实例地图及 `setChapter`、`setView`、`setAllRoutes` 语义，不通过第二次 `create()` 制作总览。

Three.js的参考是相机取景与场景状态的分离；现有SVG viewBox已能表达区域与近景。沿用已测试的取消旧镜头、落到最新状态策略，本轮不新增三维相机或另一套动画循环。

交互地图折叠、离开视口或页面隐藏时，路线直接处于可读完成态；重新可见可手动重播。被动切章与“全部路线”不自动将页面拉到地图。重播按钮在已展开地图内只重播，不再页面居中。暂停、减少动态和Anime.js失败时，图文与操作仍可用；减少动态时镜头立即到位、路线完整出现，音乐由读者独立开关。

## 验收与交付

自动检查：总览恰有四条对应既有数据的路线；分章图各用自己的局部几何；SVG ID唯一；渲染幂等；白名单、许可和缓存指纹同步。导航覆盖短屏、1→4→2、反向滚动、中断、模块失败和生命周期。

浏览器检查：320×568、390×844、768×1024、844×390、900×600、901×600、1280×480、1440×900；覆盖旋转、字体放大、无脚本和减少动态。背景总览始终不变；被动滚动不搬节点、不回拉；分别截图并查看背景、章节和地图说明。

保留历史与现代地点区别、未落点的九溪口、概化地形说明、来源及CC BY-SA 4.0，不新增历史断言或坐标，不改变音乐默认关闭。完成实施后按项目既有授权构建、提交并推送既有远程、更新根首页并验证线上；用户当次另有限制则从其要求。本轮文档阶段不发布。
